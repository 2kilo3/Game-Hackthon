**AI 游戏赛道 · 不重要队 · 游戏版本 v1.0.0**

**打碎现代的一盆植物，让未来多一座助攻能量桩。**《时空管理局》把双时空探索与即时战斗连在一起：玩家扮演入职第一天的衍月，前往 A 街区处理异常，在 2026 年与 2209 年之间穿梭，用过去的行动改变未来战局。作品面向喜欢像素动作、剧情探索和场景互动的玩家。

## 3. 核心玩法与完整案例

当前版本包含双时空场景、八方向动作战斗、格挡与闪避、现代与未来 Boss、钩爪拾取与天赋成长、花盆与能量桩因果机制，以及 11 段交互剧情。未来 Boss 战后衔接“未完待续”、淡出与“游戏结束”，可返回主菜单重开。

### 案例：用现代花盆改变未来 Boss 战

**场景与输入。** 从新游戏进入现代场景，选定一只花盆，靠近后按 J 攻击直至打碎。记住它的位置，保留另一只花盆作为对照。按 R 进入未来，推进流程使未来 Boss 登场，并将其引入对应能量桩的攻击范围。

**处理过程。**

1. 花盆破坏事件按编号写入本局 `World` 状态，现代花盆与未来能量桩一一对应。
2. 对应能量桩读取破坏状态，播放激活动画并点亮。
3. 能量桩检查目标是否为已登场、存活、处于当前场景且在范围内的未来 Boss；满足条件后，按攻击间隔发射激光并结算伤害。

**可观察输出。** 被破坏花盆对应的能量桩点亮，满足目标条件时发出激光并协助伤害 Boss；未破坏花盆对应的桩保持未激活。桩已点亮但暂未发射时，先检查 Boss 是否登场及是否进入范围。

**复现与对照。** 返回主菜单开始新游戏，改为保留同一只花盆，再切换未来观察该位置。重开会清除本局花盆状态，可重复比较两种结果。

本案例使用团队自建的游戏场景、物件编号与规则状态，输入来自玩家实际操作，输出由本地游戏逻辑实时计算；未使用外部数据集、企业数据、模拟 API 或伪造的服务返回。

## 4. 现场演示准备

1. 提前完整解压，连接电源，确认键盘、音量与显卡驱动正常；优先使用本地显示器运行。
2. 预演一次“开始游戏 → 推进对白 → 移动与攻击 → R 切换时空”，确认按键与说明一致。
3. 正式演示按“开场任务 → 现代战斗 → 钩爪与天赋 → 花盆因果 → 未来 Boss → 结束画面”展开。先打碎花盆，再进入未来展示对应结果。
4. 保留一份完整运行包作为恢复副本。现场无需联网或登录；若重启程序，按新一局重新演示。

## 5. 故障恢复

| 现象 | 恢复方法 |
|---|---|
| 找不到 EXE | 本提交文件夹或最新版运行包内打开 `时空管理局/`；历史 v1.0.0 发布包内打开 `windows/`。不要从压缩包内直接启动 |
| 黑屏或图形驱动报错 | 更新电脑或显卡厂商驱动，确认支持 OpenGL 3.3；从远程桌面切回本地显示环境后重试 |
| 键位与说明不同 | 在按键设置中恢复默认；必要时退出游戏，将下列 `keybinds.cfg` 改名备份，再启动生成默认配置 |
| 对白期间无法战斗 | 按 Enter / Space 推进，或按 Esc 关闭当前段落，待对白结束后继续 |
| 能量桩点亮却没有激光 | 确认处于未来、Boss 已登场且存活，并将其引入该桩范围，等待攻击间隔 |
| 文件损坏、缺资源或无法启动 | 重新完整解压，核对 EXE 哈希；若从仓库取得的是很小的文本指针文件，改从发布页下载运行包 |
| 程序无响应 | 通过任务管理器结束该游戏进程，再重新启动；本局进度随重开重置 |

按键配置：`%APPDATA%/Godot/app_userdata/2.5D Pixel Demo/keybinds.cfg`。

在本提交文件夹打开 PowerShell，可核对：

```powershell
Get-FileHash -LiteralPath '.\时空管理局\时空管理局_剧情完整版.exe' -Algorithm SHA256
```

## 6. 技术与 AI 开发说明

项目使用 **Godot 4.7.2 stable + GDScript**，以 2D 场景、八方向序列帧和按 Y 排序形成 2.5D 像素表现。`Timeline` 管理现代 / 未来切换，`World` 保存场景与花盆状态，角色和 Boss 脚本执行战斗行为，`DialogueHost` 接收事件并管理对白队列、暂停与结局转场。

| AI / 开发工具 | 用途 |
|---|---|
| DeepSeek Harness | 主要程序开发与玩法实现 |
| Codex | 调试、错误修复、模块接入、剧情及交付整理 |
| GPT / ImageGen、Meowa | 图像与动作素材生成、辅助处理和整合 |
| Godot、Godot MCP | 引擎开发、编辑器交互与无界面验证；MCP 为开发工具 |

**AI 用于开发与素材生产。**游玩时，战斗、对白和因果规则由本地程序执行，不调用大模型。

## 7. 源码运行（开发者选读）

普通玩家直接运行 EXE。开发者使用 Godot **4.7.2 stable 标准版**；源码获取需要 Git 与 Git LFS，导出需要匹配的 Windows 导出模板。

```powershell
git lfs install
git clone --branch v1.0.0 https://github.com/2kilo3/Game-Hackthon.git
cd Game-Hackthon
git lfs pull
godot --editor --path ./godot --import
godot --path ./godot
```

`godot` 为本机 Godot 程序命令；如未加入 PATH，用 `& 'Godot程序的完整路径.exe'` 替换。首次导入应等待完成。若导入异常退出，重新打开工程完成导入，确认资源错误消失后再运行。Godot MCP 插件为可选开发集成。

冻结源码标签：`v1.0.0`；commit：`30b0368f8d380b0a0d6d1d33b9fcd15b03198027`。核心机制可查阅该标签下 `godot/scripts/world.gd`、`energy_pylon.gd`、`timeline.gd`；剧情入口为 `dialogue_host.gd` 与 `story_dialogue.gd`。
