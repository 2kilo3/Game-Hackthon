# Game Hackthon · 时空管理局

**AI 游戏赛道 · 不重要队 · 冻结版本 v1.0.0**

改变现在，影响未来。《时空管理局》是一款面向像素动作与剧情探索玩家的双时空游戏。衍月在入职第一天前往 A 街区处理异常，在 2026 年的现代与 2209 年的未来之间穿梭。玩家在现代破坏场景物件，可以改变未来的战斗条件；过去的操作成为可观察、可利用的因果结果。

## 直接开始游玩

1. 从 [v1.0.0 发布页](https://github.com/2kilo3/Game-Hackthon/releases/tag/v1.0.0) 下载 `AI游戏_不重要_时空管理局.zip`，或使用参赛提交的同名压缩包。
2. 在 Windows 电脑上**先完整解压**到普通文件夹。无需安装引擎，不要在压缩包预览窗口里直接运行。
3. 双击 `windows/时空管理局_剧情完整版.exe`，选择“开始游戏”。无需账号、API 密钥、网络或模型服务。

源码仓库：https://github.com/2kilo3/Game-Hackthon

引擎和游戏资源已经嵌入 EXE，不需要另找 PCK、Python、Node.js、Godot 或 AI 插件。`windows` 内的文本文件是引擎和字体版权声明，请随程序保留。

### 环境

| 项目 | 要求 |
|---|---|
| 交付平台 | Windows x86_64；建议 Windows 10/11 64 位 |
| 图形 | 支持 OpenGL 3.3 的显卡及正常安装的显卡驱动；使用 Godot Compatibility 渲染器 |
| 磁盘 | 建议预留 500 MB，用于解压、运行和配置文件 |
| 输入 | 键盘；主菜单和设置支持鼠标 |
| 网络与服务 | 游玩不依赖网络、登录、数据库或 AI 推理服务 |

本版本是 Windows 可执行文件，macOS、Linux 不能直接运行此 EXE。标题栏保留工程原名“2.5D Pixel Demo”，主界面显示“时空管理局”，属于同一交付版本。

## 核心功能与演示案例

已完成主菜单与设置、八方向动作战斗、格挡与闪避反馈、现代和未来场景切换、两阶段 Boss 流程、钩爪与天赋、跨时空花盆/能量桩机制，以及 11 段交互剧情。未来 Boss 战后经“未完待续”、淡出黑屏进入“游戏结束”，可返回主菜单重开。

### 案例：让过去的选择改变未来战局

**输入：** 在现代场景靠近花盆，按 J 攻击直至打碎，随后按 R 切换未来。让未来 Boss 登场并进入对应能量桩的助攻范围。

**处理：** 现代花盆破坏事件按编号写入本局世界状态；未来同一位置的能量桩读取该状态，播放激活动画。能量桩只对已经登场、存活且位于范围内的未来 Boss 发起攻击。

**输出：** 对应能量桩点亮并发出激光，协助对未来 Boss 造成伤害。可对照未破坏的花盆观察尚未激活的桩。该案例使用游戏自身场景和状态，不接企业数据、模拟接口或在线服务。

现场推荐流程：开始游戏及对白 → 现代战斗 → 钩爪/天赋 → R 穿梭 → 花盆与能量桩因果 → 未来 Boss 与结局。演示时保留足够空间展示战斗，不以静态材料替代实际操作。

## 运行准备与故障恢复

- 演示前完整解压运行包，使用本地磁盘，确认键盘、声音和显卡驱动工作正常；笔记本接通电源。先试一次开始游戏与时空切换。
- 键位与说明不一致：进入按键设置恢复默认。配置位于 `%APPDATA%/Godot/app_userdata/2.5D Pixel Demo/keybinds.cfg`；退出程序后可把该文件改名为备份，再启动恢复默认配置。
- 启动黑屏或提示图形驱动不支持：更新电脑厂商/显卡厂商驱动，确认支持 OpenGL 3.3；远程桌面或基础显示驱动可能无法提供所需图形能力。
- 文件损坏或提示缺资源：重新完整解压，核对下面的 EXE SHA-256。GitHub 下载的几十字节文本不是程序，而是 Git LFS 指针，请改用发布页下载。
- 无响应：关闭该游戏进程后重新启动。当前版本按局运行，重开从头开始；后续剧情章节不包含在本次提交版本中。

## 技术实现与 AI 开发

使用 **Godot 4.7.2 stable、GDScript 和 Compatibility 渲染器**。2D 场景、八方向序列帧与按 Y 排序形成 2.5D 像素表现。`Timeline` 管理时空状态，`World` 管理敌人、场景与跨时空因果；玩家、普通敌人和 Boss 使用各自的行为逻辑。菜单通过信号连接宿主；`DialogueHost` 接收战斗、拾取、天赋、穿梭与死亡事件，将对白排队、去重并处理暂停与结局转场。

| Godot 与 Godot MCP | 引擎开发、编辑器交互与无界面验证；MCP 是开发工具，玩家无需安装 |

AI 参与的是开发和素材生产；运行时的战斗、剧情与场景由本地程序执行，不需要实时调用大模型。

## 源码运行与构建（开发者）

普通玩家只使用 EXE。开发者安装 Godot **4.7.2 stable 标准版**及对应 Windows 导出模板；不需要 .NET 版。克隆仓库时需要 Git LFS：

```powershell
git lfs install
git clone https://github.com/2kilo3/Game-Hackthon.git
cd Game-Hackthon
git lfs pull
godot --editor --path ./godot --import
godot --path ./godot
```

`godot` 代表本机 Godot 可执行文件，可替换为完整安装路径。首次无缓存的 headless 导入在本机曾于字体导入阶段异常退出；资源生成后重新运行导入命令成功。遇到同样情况可再执行一次导入，确认无错误后运行；这不影响已导出的免安装 EXE。源码编辑器中的 Godot MCP 插件属于可选开发集成，不是游戏运行依赖。

```powershell
# 回归检查，使用 Godot 编辑器/控制台程序，不使用发布 EXE 的 --script 参数
godot --headless --path ./godot --script res://tests/test_story.gd
# 导出自定义构建，不覆盖随仓库冻结的发布 EXE
New-Item -ItemType Directory -Force ./godot/build/windows
godot --headless --path ./godot --export-release 'Windows Desktop' ./build/windows/TimeBureau.exe
```
